# **人物备忘录 App — 产品需求文档（PRD）**

Demo 项目

产品需求文档 v1.0

**项目名称：** 人物备忘录（Person Memo）

**产品定位：** 一款以人物为核心的信息记录与管理工具。

**核心业务：** 用户可以创建人物档案，并为每个人添加多个描述词条，通过分类、搜索和编辑功能管理人物信息。

# **一、项目背景**

在日常生活和工作中，用户会认识很多人，例如朋友、同事、同学、客户等。随着认识的人越来越多，仅靠记忆很难记住每个人的个人信息、兴趣爱好、性格特点和经历。

因此，需要开发一款人物备忘录 App，帮助用户记录和管理与人物相关的信息。

本产品不定位为社交软件、即时通讯软件或传统通讯录，而是一个以人物为主体的个人信息记录工具。

# **二、产品目标**

1. 支持用户创建和管理人物档案。
2. 支持为每个人添加多个描述词条。
3. 支持对人物和描述词条进行分类管理。
4. 支持快速搜索人物及其相关信息。
5. 支持本地持久化存储，保证数据不会因为关闭 App 而丢失。
6. 提供简单、清晰、易操作的使用体验。

# **三、用户角色与使用场景**

## **3.1 用户角色**

普通用户，无需注册账号即可使用 App。

## **3.2 核心使用场景**

| 场景     | 具体描述           |
| ------ | -------------- |
| 认识新朋友  | 添加人物档案，记录姓名和关系 |
| 了解一个人  | 记录职业、兴趣、性格等信息  |
| 记录重要信息 | 记录生日、喜好、工作经历等  |
| 更新人物信息 | 对已有的人物描述进行修改   |
| 查找某个人  | 根据姓名或描述词条搜索    |
| 整理人物关系 | 按朋友、同事、家人等分类查看 |

# **四、功能需求**

## **4.1 人物管理模块**

核心功能

### **4.1.1 添加人物**

用户可以创建一个新的人物档案。

人物信息字段：

| 字段   | 是否必填 | 说明             |
| ---- | ---- | -------------- |
| 姓名   | 是    | 人物姓名           |
| 头像   | 否    | 人物头像           |
| 人物关系 | 是    | 朋友、同事、家人、同学、其他 |
| 性别   | 否    | 男、女、未知         |
| 个人简介 | 否    | 对人物的简单介绍       |
| 创建时间 | 自动生成 | 人物创建时间         |
| 更新时间 | 自动生成 | 最后修改时间         |

业务规则：

- 姓名不能为空。
- 创建人物后自动生成唯一 ID。
- 默认头像可以使用系统提供的占位图片。
- 人物关系采用预设选项。
- 创建成功后进入人物详情页面。

### **4.1.2 编辑人物**

用户可以修改已创建人物的基本信息。

支持修改：

- 姓名。
- 头像。
- 人物关系。
- 性别。
- 个人简介。

保存成功后，人物信息及更新时间同步更新。

### **4.1.3 删除人物**

用户可以删除不再需要的人物档案。

业务规则：

- 删除前需要二次确认。
- 删除人物时，同时删除该人物关联的所有描述词条。
- 删除后返回人物列表。
- 删除操作不可恢复，第一版不实现回收站。

### **4.1.4 查看人物列表**

首页展示所有已经创建的人物。

列表展示信息：

- 人物头像。
- 人物姓名。
- 人物关系。
- 个人简介。
- 描述词条数量。
- 最后更新时间。

列表默认按照最近更新时间倒序排列。

支持：

- 点击人物进入详情页面。
- 点击添加按钮创建人物。
- 按人物关系筛选。
- 按姓名排序或更新时间排序。

## **4.2 人物描述词条模块**

核心功能 · 产品核心

这是本 App 最重要的业务模块。

一个人物可以拥有多个描述词条，每个词条独立管理。

### **4.2.1 添加描述词条**

用户进入某个人物详情页面后，可以添加描述词条。

词条信息字段：

| 字段   | 是否必填 | 说明          |
| ---- | ---- | ----------- |
| 词条名称 | 是    | 简短描述，例如喜欢篮球 |
| 词条分类 | 是    | 兴趣、职业、性格等   |
| 详细描述 | 否    | 对词条内容进行补充   |
| 创建时间 | 自动生成 | 词条创建时间      |
| 更新时间 | 自动生成 | 最后修改时间      |

预设词条分类：

| 分类   | 示例               |
| ---- | ---------------- |
| 职业   | Android 开发工程师、教师 |
| 兴趣爱好 | 篮球、摄影、游戏         |
| 性格特点 | 开朗、细心、内向         |
| 生活习惯 | 喜欢早起、喜欢健身        |
| 饮食偏好 | 喜欢咖啡、不吃辣         |
| 教育经历 | 毕业院校、专业          |
| 工作经历 | 工作公司、工作年限        |
| 重要日期 | 生日、纪念日           |
| 其他   | 无法归入上述分类的信息      |

业务规则：

- 每个人物可以添加多条词条。
- 同一个人物允许添加多个相同分类的词条。
- 词条必须关联一个已存在的人物。
- 词条名称不能为空。
- 词条分类不能为空。
- 详细描述允许为空。
- 创建成功后自动关联当前人物 ID。

### **4.2.2 编辑描述词条**

用户可以修改已有词条。

支持修改：

- 词条名称。
- 词条分类。
- 详细描述。

保存后自动更新词条更新时间。

### **4.2.3 删除描述词条**

用户可以删除不需要的词条。

业务规则：

- 删除前需要二次确认。
- 只删除当前词条，不影响人物档案。
- 删除后人物详情页面同步刷新。

### **4.2.4 查看描述词条**

人物详情页面展示该人物的全部词条。

支持：

- 按创建时间排序。
- 按更新时间排序。
- 按词条分类筛选。
- 点击词条查看完整描述。
- 点击词条进入编辑页面。

## **4.3 人物分类模块**

辅助功能

对人物进行关系分类，方便用户管理。

默认分类：

- 朋友
- 同事
- 家人
- 同学
- 客户
- 其他

功能需求：

1. 创建人物时必须选择人物关系。
2. 支持修改人物关系。
3. 首页支持按关系筛选人物。
4. 展示每个分类下的人物数量。
5. 支持查看全部人物。

第一版使用固定分类，不提供自定义分类功能。

## **4.4 搜索模块**

辅助功能

提供全局搜索功能，帮助用户快速找到人物。

搜索范围：

| 搜索内容 | 说明         |
| ---- | ---------- |
| 人物姓名 | 根据姓名匹配人物   |
| 人物简介 | 根据简介内容匹配   |
| 词条名称 | 根据词条名称匹配   |
| 词条描述 | 根据词条详细描述匹配 |

业务规则：

- 支持关键词模糊匹配。
- 搜索结果展示人物基本信息。
- 如果匹配到某条词条，应显示对应的词条名称。
- 没有搜索结果时展示空状态。
- 清空搜索内容后恢复人物列表。

例如：搜索「篮球」，可以找到描述词条中包含篮球的人物。

## **4.5 人物详情模块**

核心功能

人物详情页面用于集中展示一个人物的所有信息。

页面包含：

**人物基本信息**

- 头像。
- 姓名。
- 人物关系。
- 性别。
- 个人简介。
- 创建时间。
- 更新时间。

**人物描述信息**

- 词条总数。
- 不同分类的词条。
- 每个词条的名称。
- 每个词条的详细描述。

**操作功能**

- 编辑人物。
- 删除人物。
- 添加描述词条。
- 编辑描述词条。
- 删除描述词条。
- 按分类筛选词条。

## **4.6 本地数据管理模块**

核心功能

第一版采用本地数据库存储，不需要用户注册，不需要服务端。

功能需求：

1. 人物数据本地持久化。
2. 词条数据本地持久化。
3. App 关闭后数据不能丢失。
4. App 重新打开后恢复之前的数据。
5. 修改人物信息后同步更新。
6. 删除人物时同步删除关联词条。
7. 删除词条后同步更新人物词条数量。

技术建议：使用 Room 实现本地数据库。

# **五、页面及导航需求**

第一版规划以下页面：

| 页面    | 主要功能         |
| ----- | ------------ |
| 人物首页  | 人物列表、搜索、分类筛选 |
| 添加人物页 | 创建人物档案       |
| 编辑人物页 | 修改人物信息       |
| 人物详情页 | 展示人物信息和词条    |
| 添加词条页 | 创建人物描述词条     |
| 编辑词条页 | 修改人物描述词条     |
| 词条详情页 | 查看完整词条描述     |

页面导航规则：

1. App 启动后默认进入人物首页。
2. 首页点击人物进入人物详情页。
3. 首页点击添加按钮进入添加人物页。
4. 人物详情页点击添加词条进入添加词条页。
5. 人物详情页点击编辑按钮进入编辑人物页。
6. 点击某条词条进入词条详情页。
7. 所有新增和编辑操作保存成功后返回上一级页面，并刷新数据。

# **六、非功能需求**

## **6.1 性能要求**

- 首页人物列表正常加载。
- 人物和词条操作完成后及时更新界面。
- 搜索操作响应及时。
- 不应因为大量词条而明显卡顿。

## **6.2 数据安全**

- 数据保存在本地数据库。
- 不需要网络权限。
- 不需要用户账号体系。
- 不向第三方服务器上传人物信息。
- 删除操作需要用户确认。

## **6.3 兼容性**

- 支持 Android 7.0（API 24）及以上版本。
- 支持不同屏幕尺寸。
- 兼容常见手机分辨率。
- 适配系统深色模式可以作为后续优化项。

# **七、数据模型需求**

第一版采用两张核心数据表。

## **7.1 Person 人物表**

| 字段           | 类型      | 说明   |
| ------------ | ------- | ---- |
| id           | Long    | 主键   |
| name         | String  | 姓名   |
| avatarUri    | String? | 头像地址 |
| relationship | String  | 人物关系 |
| gender       | String? | 性别   |
| description  | String? | 个人简介 |
| createdAt    | Long    | 创建时间 |
| updatedAt    | Long    | 更新时间 |

## **7.2 PersonEntry 人物词条表**

| 字段        | 类型      | 说明      |
| --------- | ------- | ------- |
| id        | Long    | 主键      |
| personId  | Long    | 关联人物 ID |
| title     | String  | 词条名称    |
| category  | String  | 词条分类    |
| content   | String? | 详细描述    |
| createdAt | Long    | 创建时间    |
| updatedAt | Long    | 更新时间    |

## **7.3 数据关系**

- 一个 Person 可以关联多个 PersonEntry。
- 一个 PersonEntry 只能属于一个 Person。
- PersonEntry 通过 personId 关联 Person 的 id。
- 删除 Person 时级联删除其关联的 PersonEntry。

# **八、版本规划**

为了避免 Demo 开发范围过大，建议将需求分为三个版本。

| 版本   | 功能范围                            | 优先级  |
| ---- | ------------------------------- | ---- |
| V1.0 | 添加、编辑、删除人物；添加、编辑、删除词条；人物详情；本地存储 | 必须完成 |
| V1.1 | 人物分类筛选、全局搜索、词条分类筛选、排序           | 后续完成 |
| V1.2 | 头像选择、自定义分类、数据导出、数据备份、深色模式优化     | 可选扩展 |

# **九、V1.0 验收标准**

第一版开发完成后，需要满足以下条件：

- 用户可以成功添加人物。
- 用户可以编辑人物基本信息。
- 用户可以删除人物。
- 用户可以查看人物列表。
- 用户可以进入人物详情页面。
- 用户可以给人物添加多个描述词条。
- 用户可以编辑描述词条。
- 用户可以删除描述词条。
- 用户可以查看人物的全部词条。
- 每条词条都正确关联所属人物。
- 删除人物后，其关联词条也被删除。
- App 关闭后重新打开，之前的数据仍然存在。
- 人物信息或词条发生变化后，相关页面能够同步更新。

# **十、项目开发边界**

为了保证这个 Demo 的学习价值，第一版明确不开发以下功能：

| 暂不开发的功能 | 原因         |
| ------- | ---------- |
| 用户注册、登录 | 不需要账号体系    |
| 云端数据库   | 先练习本地数据持久化 |
| 好友关系和社交 | 不属于核心业务    |
| 即时聊天    | 不属于核心业务    |
| AI 人物分析 | 增加不必要的复杂度  |
| 多人协作    | 暂时不需要      |
| 消息推送    | 暂时不需要      |
| 复杂统计分析  | 不是核心功能     |

**最终产品定位：一个本地运行、以人物为中心、通过描述词条记录和管理人物信息的 Android 原生 App。**

这份文档可以直接作为后续 Android 开发的需求依据。建议 V1.0 严格按照验收标准实现，先把人物管理、词条管理和 Room 本地存储三个核心部分做好。
