# Memorandum V1.1 产品需求文档（PRD）

**版本：** V1.1\
**产品名称：** Memorandum\
**版本主题：** 全局悬浮助手与人物对话数据收集

---

## 一、产品背景

Memorandum 是一款人物记忆管理工具，帮助用户记录、整理和查询与不同人物相关的信息。

V1.0 已经实现基础人物管理和人物描述词条管理，包括人物新增、编辑、删除、详情查看，以及基于 Room 的本地数据持久化。

但在实际使用过程中，用户通常是在微信、QQ、WhatsApp、Telegram、钉钉等第三方应用中与他人交流。如果每次想记录人物信息，都需要退出当前应用并打开 Memorandum，操作成本较高。

因此，V1.1 计划引入全局悬浮助手，让用户在其他应用中也能快速查询人物信息、添加人物和收集对话内容。

## 二、V1.1 产品目标

V1.1 的核心目标是：

**让用户能够在不离开当前应用的情况下，快速查询人物、创建人物，并将聊天内容保存到对应人物档案中。**

主要实现以下能力：

1. 全局悬浮助手，可以在其他应用中使用。
2. 快速搜索和选择已有的人物。
3. 快速添加新人物。
4. 主动读取系统剪贴板中的文本。
5. 手动输入和编辑对话内容。
6. 将对话内容关联到指定人物。
7. 将原始对话数据保存到本地数据库。

V1.1 重点解决数据采集和人物关联问题，不涉及后续智能化数据处理。

## 三、产品整体结构

Memorandum V1.1 包含两个主要使用入口。

### 3.1 独立 App

定位：完整的人物档案管理中心。

主要功能：

- 人物列表与搜索。
- 人物新增、编辑和删除。
- 人物关系分类管理。
- 人物标签及标签分类管理。
- 人物完整详情查看。
- 人物词条新增、编辑和删除。
- 历史对话记录查看与管理。
- 悬浮助手开启、关闭及相关设置。

独立 App 负责完整的数据管理能力。

### 3.2 全局悬浮助手

定位：跨应用人物记忆快捷工作台。

主要功能：

- 悬浮球显示、拖动和展开。
- 快速搜索人物。
- 快速添加人物。
- 查看人物基本信息。
- 查看已有的人物标签和记忆词条。
- 读取剪贴板文本。
- 手动输入和编辑对话内容。
- 选择人物并保存对话。

悬浮助手只提供高频、轻量的操作，不承担完整的人物管理职责。

## 四、功能需求

### 4.1 全局悬浮球

**功能目标：** 在其他应用中提供 Memorandum 的快捷入口。

功能要求：

1. 用户可以主动开启和关闭悬浮助手。
2. 开启后显示全局悬浮球。
3. 悬浮球支持拖动。
4. 悬浮球位置能够记忆，下次启动后恢复。
5. 点击悬浮球展开快捷面板。
6. 再次点击或执行关闭操作可以收起面板。
7. 悬浮助手在获得系统授权后，可以覆盖显示在其他允许覆盖的应用之上。

### 4.2 悬浮快捷面板

**功能目标：** 提供人物查询、人物创建和对话收集的快捷操作入口。

面板主要包含：

- 人物搜索区域。
- 最近使用或搜索到的人物列表。
- 添加新人物入口。
- 人物基本信息展示区域。
- 对话内容收集区域。

面板应尽量简洁，避免承载复杂的管理页面。

### 4.3 人物查询

**功能目标：** 在不退出当前应用的情况下查询已有的人物信息。

功能要求：

1. 支持根据人物姓名搜索。
2. 支持展示搜索结果。
3. 支持选择指定人物。
4. 支持查看人物姓名、头像、简介等基本信息。
5. 支持查看人物已有的关系分类。
6. 支持查看人物已有的标签和描述词条。
7. 支持进入人物相关的快捷操作。

注意：

- 悬浮助手只展示已有的关系分类和标签。
- 不提供关系分类的新增、编辑和删除。
- 不提供标签分类的新增、编辑和删除。
- 不提供完整的人物档案编辑能力。

### 4.4 快速添加人物

**功能目标：** 用户在第三方应用中遇到新人物时，可以直接通过悬浮助手创建人物。

功能要求：

1. 在人物搜索或选择区域提供「添加新人物」入口。
2. 支持填写人物姓名，姓名必填。
3. 支持填写人物简介，选填。
4. 创建成功后立即生成对应的人物数据。
5. 创建成功后自动选中刚创建的人物。
6. 用户可以继续收集对话内容，并将其保存到该人物名下。

V1.1 快速添加人物不包含：

- 人物关系分类选择和管理。
- 标签分类选择和管理。
- 复杂人物档案编辑。
- 人物头像管理。

上述完整管理能力继续由独立 App 提供。

### 4.5 对话内容收集

**功能目标：** 用户能够从第三方聊天应用中主动获取聊天文本，并保存到 Memorandum。

支持两种收集方式。

#### 方式一：剪贴板收集

使用流程：

1. 用户在微信、QQ 等第三方应用中复制聊天消息。
2. 用户点击 Memorandum 悬浮球。
3. 展开悬浮助手。
4. 用户主动点击「读取剪贴板」。
5. 系统读取当前剪贴板中的文本。
6. 在悬浮面板中展示文本内容。
7. 用户可以编辑文本。
8. 用户选择对应人物。
9. 保存对话记录。

要求：

- 必须由用户主动触发剪贴板读取。
- 读取后应展示内容预览。
- 用户可以修改或删除部分文本。
- 不允许未经用户确认就自动保存。
- 不允许根据剪贴板内容自动判断聊天对象。

#### 方式二：手动输入

使用流程：

1. 用户打开悬浮助手。
2. 进入对话收集区域。
3. 手动输入或粘贴对话内容。
4. 选择对应人物。
5. 保存对话记录。

要求：

- 支持多行文本。
- 支持编辑。
- 支持取消操作。
- 内容为空时不允许保存。

### 4.6 人物关联

**功能目标：** 确保每条对话记录都明确归属于指定人物。

功能要求：

1. 保存对话前必须选择一个人物。
2. 可以从搜索结果中选择人物。
3. 可以选择刚刚创建的人物。
4. 未选择人物时不允许保存为正式关联的对话记录。
5. 不自动匹配聊天对象。
6. 不根据聊天内容推测人物身份。

### 4.7 对话记录管理

**功能目标：** 将收集到的原始对话保存到本地数据库。

每条对话记录至少包含：

| 字段               | 说明            |
| ---------------- | ------------- |
| id               | 对话记录唯一标识      |
| personId         | 关联人物 ID       |
| content          | 原始对话文本        |
| source           | 数据来源：剪贴板或手动输入 |
| conversationTime | 对话发生时间，可为空    |
| createdAt        | 记录创建时间        |

功能要求：

1. 对话记录保存到 Room 本地数据库。
2. 对话记录必须关联人物。
3. 保存后能够在对应人物详情中查看。
4. 支持查看最近收集的对话记录。
5. 原始对话文本应完整保留，不进行自动分析和改写。

### 4.8 独立 App 与悬浮助手的数据共享

独立 App 和悬浮助手使用同一套本地数据库和数据访问层。

数据共享要求：

1. 独立 App 新增人物后，悬浮助手能够查询到。
2. 悬浮助手新增人物后，独立 App 能够查询到。
3. 悬浮助手保存对话后，独立 App 能够查看。
4. 独立 App 修改人物信息后，悬浮助手展示最新数据。
5. 原有 V1.0 人物和词条数据保持兼容。

## 五、功能边界

V1.1 只负责原始数据的获取、人物关联、存储和基础展示。

以下功能明确不属于 V1.1：

| 功能              | 规划版本 |
| --------------- | ---- |
| AI 对话分析         | V1.2 |
| AI 结构化信息提取      | V1.2 |
| SQLite FTS 全文检索 | V1.2 |
| 中文分词优化          | V1.2 |
| 自动生成人物标签        | V1.2 |
| 人物记忆自动更新        | V1.2 |
| 信息去重与整理         | V1.2 |
| 智能识别聊天对象        | 暂不规划 |
| 悬浮窗广告           | 不规划  |
| 独立 App 主页广告     | V1.3 |

特别说明：

V1.1 保存的对话数据主要作为原始数据来源，为 V1.2 后续智能处理提供基础。

本版本不负责对这些数据进行深度加工。

## 六、非功能需求与技术约束

### 6.1 Android 系统权限

悬浮助手需要用户授予悬浮窗权限。

使用 Android 系统提供的悬浮窗能力实现跨应用显示。

### 6.2 剪贴板访问

Android 对后台剪贴板访问存在系统限制。

因此 V1.1 采用用户主动打开悬浮助手并点击读取剪贴板的方式，不依赖后台持续监听剪贴板。

### 6.3 数据持久化

继续使用 Room 作为本地数据库。

新增对话记录数据实体，与现有 PersonEntity 建立关联。

### 6.4 数据安全

1. 不主动读取第三方应用私有数据库。
2. 不在后台持续抓取第三方应用聊天内容。
3. 用户主动选择并确认需要保存的内容。
4. 原始对话数据保存在本地数据库。

## 七、核心业务流程

### 7.1 已有人物的对话收集

第三方聊天应用复制消息 → 点击悬浮球 → 读取剪贴板 → 选择人物 → 编辑文本 → 保存 → Room 数据库。

### 7.2 新人物的对话收集

第三方聊天应用复制消息 → 点击悬浮球 → 读取剪贴板 → 添加新人物 → 填写姓名和简介 → 创建并自动选中人物 → 保存对话 → Room 数据库。

### 7.3 人物信息查询

第三方应用 → 点击悬浮球 → 搜索人物 → 选择人物 → 查看基本信息、关系分类、标签和记忆词条。

## 八、V1.1 验收标准

### 悬浮助手

- 能够主动开启和关闭悬浮助手。
- 悬浮球能够在其他允许覆盖的应用中显示。
- 悬浮球能够拖动。
- 能够记忆悬浮球位置。
- 点击悬浮球能够展开和收起面板。

### 人物管理

- 能够搜索已有的人物。
- 能够查看人物基本信息。
- 能够查看已有的人物关系分类。
- 能够查看已有的人物标签和词条。
- 能够快速添加人物。
- 快速添加人物时姓名必填、简介选填。
- 创建人物成功后自动选中该人物。

### 对话收集

- 能够主动读取剪贴板文本。
- 能够预览剪贴板内容。
- 能够编辑剪贴板内容。
- 能够手动输入对话内容。
- 保存前必须选择人物。
- 能够保存对话记录到 Room。
- 能够在人物详情中查看已保存的对话。
- 能够查看最近收集的对话记录。

### 数据兼容

- 独立 App 与悬浮助手共享人物数据。
- 独立 App 与悬浮助手共享对话数据。
- 不影响 V1.0 原有人物 CRUD 功能。
- 不影响 V1.0 原有词条 CRUD 功能。

## 九、版本总结

V1.1 的核心不是打造一个复杂的悬浮窗，而是建立一套跨应用的人物记忆数据采集入口。

独立 App 负责完整的人物档案管理，悬浮助手负责快速查询、快速创建和对话收集。

两个入口共享同一套数据体系，为 V1.2 的人物记忆智能处理打下基础。

**V1.1 核心原则：快速获取、明确归属、原始保存，不做智能加工。**

**本次 PRD 的版本边界已经收敛：**

- V1.1：悬浮助手、快速添加人物、对话收集与存储。
- V1.2：AI、全文检索、人物记忆智能处理。
- V1.3：独立 App 主页广告商业化探索。
