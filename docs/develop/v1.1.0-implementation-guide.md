# Memorandum V1.1.0 需求原型澄清与 Android 原生实现指南

> 本文档基于 [v1.1.0 PRD](../PRDs/v1.1.0.md)、[v1.1.0 交互原型](../prototype/v1.1.0.html)（预览图 [v1.1.0.png](../images/v1.1.0.png)）以及当前代码库基线编写，旨在为后续负责 V1.1.0 开发的模型或工程师提供**无歧义的原型澄清**与**可落地的 Android 原生实现指导**。

## 1. 当前代码库基线（动手前必须了解）

当前工程已经完成了 V1.0.x 演进，后续在扩展 V1.1.0 时请直接复用现有基础设施，不要推倒重写：

- **架构与技术栈**：单 Activity + Jetpack Compose Material3 + Hilt (KSP) + Navigation Compose + Room (KSP)，MVI 模式（`UiState` / `Event` / `Effect`）。
- **数据库基线**：[AppDatabase.kt](../../app/src/main/kotlin/com/jfeng2048/memorandum/data/local/AppDatabase.kt) 当前为 `version = 4`，包含 5 张表：
  - `persons`（`PersonEntity`）
  - `relationships`（`RelationshipEntity`）
  - `person_relationships`（`PersonRelationshipCrossRef`，**人物与关系已是多对多**）
  - `categories`（`CategoryEntity`，词条分类支持自定义增删改）
  - `entries`（`EntryEntity`，通过 `categoryId` 关联 `categories`）
- **设计基调**（见根目录 [AGENTS.md](../../AGENTS.md)）：固定沿用「白纸 `#FFFFFF` + 1px 发丝线 `#E6E7EC` + 浅灰轨道 `#F2F2F6` + 品牌蓝 `#3478F6` + 衬线人名」体系，所有颜色集中在 `Color.kt` 与 `Tints.kt`。

## 2. 原型与需求的逐项澄清（消除歧义）

原型 [v1.1.0.html](../prototype/v1.1.0.html) 已经把 PRD 中的抽象描述具象为 5 个核心画面。实现时按以下澄清为准：

### 2.1 悬浮球（未展开态）
- **形态**：直径约 `48dp` 的圆形白色浮标，2dp 品牌蓝 `#3478F6` 描边，中间一个品牌蓝圆角方块「记」字标识（或应用标识），带柔和投影。
- **交互**：
  - 支持全屏自由拖动，松手后自动吸附到屏幕左边缘或右边缘（露出主体，略微贴边）。
  - 位置记忆：记录停靠的左右侧（`isLeft: Boolean`）与纵向百分比/像素偏移（`yOffset`）到 `AppPreferences`，下次开启或重启服务时恢复。
  - 单击悬浮球：展开悬浮快捷面板；面板打开时悬浮球收至右上角或隐藏，再次点击悬浮球或面板右上角「收起」按钮回到贴边态。

### 2.2 悬浮快捷面板（展开态 · 白色便签卡）
面板是一个浮在第三方应用之上的白色圆角卡片（圆角 `18dp`，带 `1dp` `#E6E7EC` 描边与投影），内含**三个互斥模式**，不跳转独立 App：

1. **模式 A：对话收集（默认进入）**
   - **顶栏**：标题「收集到人物档案」、右侧两个轻量操作「看档案」（切到模式 C）与「收起」。
   - **步骤 1 · 选择归属人物（必选）**：
     - 右侧提供「＋ 添加新人物」入口（切到模式 B）。
     - 内置单行搜索框「搜索人物姓名…」，下方以横向换行胶囊（FlowRow）或紧凑列表展示匹配人物（头像首字 + 姓名）。
     - **澄清**：胶囊支持再次点击取消选中；**未选中任何人物时，底部主保存按钮必须处于禁用态**（文案提示「请先选择归属人物」），严禁自动猜测或默认绑定聊天对象。
   - **步骤 2 · 对话内容（剪贴板 / 手动输入）**：
     - 标签旁明确标出当前来源（`剪贴板` 或 `手动输入`），右侧放置「读取剪贴板」按钮。
     - 点击「读取剪贴板」时才主动读取系统剪贴板文本并填入下方多行文本框；若剪贴板为空或无文本，弹出轻量提示，不覆盖用户已输入的草稿。
     - 文本框支持用户删改（例如去掉多余时间戳或无关寒暄）；用户清空或手动键入时，来源应切回 `手动输入`（或在主动读取后修改仍保留 `剪贴板` 来源标记，建议记录初始获取方式并在用户全清重写时切换为 `手动输入`）。
   - **底部操作栏**：左侧「清空」按钮 + 右侧主按钮「保存对话给 {姓名}」（文本为空或未选人时禁用）。保存成功后清空草稿并给出「已保存到「{姓名}」」Toast，不强制关闭面板，方便连续记录。

2. **模式 B：悬浮快速建人**
   - **定位**：在第三方应用里遇到通讯录中尚未建档的人时，最小成本原地建档。
   - **字段**：仅「姓名 · 必填」与「个人简介 · 选填」，**不包含**关系多选、性别、头像、词条分类管理。
   - **默认关系澄清**：由于现有数据库 `PersonEntity` + `PersonRelationshipCrossRef` 支持多对多关系，且关系表至少保留一个关系，快速建人保存时建议默认关联「其他」关系（若「其他」已被用户重命名/删除，则取 `relationships` 表第一条），或在详情页允许空关系列表兜底为 `Relationship.Unknown`。
   - **闭环**：点击「创建并选中」后立即写入 Room，**自动将该新建人物设为当前选中人物**，并自动跳回模式 A（保留用户此前已读取的剪贴板草稿！），让用户直接点保存即可完成收集。

3. **模式 C：人物档案只读预览（看档案）**
   - 展示当前选中人物的头像、衬线姓名、已有关系标签、简介，以及已有记忆词条列表（带分类色点）。
   - **边界**：全部为只读展示，不在此处提供关系编辑、词条增删改或人物删除入口；右上角点击「回收集」返回模式 A。

### 2.3 独立 App 侧的配合改动
1. **首页（`HomeScreen`）**：
   - 在顶部标题/统计行下方、搜索框上方增加一张轻量「全局悬浮助手」状态开关卡（背景 `#F2F6FF` / `#F7F7FA`，`1dp` 描边，右侧开关）。
   - 开启时：若尚未授予 `SYSTEM_ALERT_WINDOW` 权限，点击先引导跳转系统「显示在其他应用上层」设置页，授权返回后自动启动悬浮服务；已授权则直接启停前台悬浮服务。
   - 列表行副文案更新为：`{关系} · {N} 词条 · {M} 对话`；首页搜索建议同时支持命中该人物关联的原始对话内容（与词条命中逻辑一致，在列表中可提示命中来源）。
2. **人物详情页（`DetailScreen`）**：
   - 在简介/统计卡下方增加分段切换器：`记忆词条 (N)` | `原始对话 (M)`。
   - 「原始对话」列表每条卡片展示：来源标签（`剪贴板收集` / `手动输入`）、记录时间、完整原始对话正文（保留换行，不做摘要或 AI 改写），支持长按/点击弹出确认删除单条对话记录。
   - 底部「＋ 添加词条」按钮仅在「记忆词条」Tab 下展示，避免误导。
3. **最近收集的对话总览（可选独立入口）**：
   - PRD 4.7 提到「支持查看最近收集的对话记录」。可在首页顶栏（例如「随便翻一个」「关系管理」旁）增加轻量入口「对话记录」，或在首页搜索/详情中优先呈现；建议新增一个轻量的 `ConversationListScreen`（按 `createdAt` 倒序展示全部人物的最近对话，点击可直接跳往对应人物详情的「原始对话」Tab）。

## 3. 严格边界（实现时不可越界）

- **严禁后台监听剪贴板**：绝不允许在 Service 里注册 `OnPrimaryClipChangedListener` 静默抓取，只能在用户点击「读取剪贴板」按钮时主动调用 `ClipboardManager.getPrimaryClip()`。
- **严禁自动匹配聊天对象**：绝不允许用无障碍服务（`AccessibilityService`）抓取微信/QQ 界面标题，也不允许根据对话文本中的人名自动选中人物。
- **严禁未经确认自动保存**：读取剪贴板后必须先在文本框展示预览，由用户确认人物并点击保存按钮后才写入 Room。
- **严禁提前引入 V1.2/V1.3 能力**：不做 AI 摘要、不做自动提取词条、不做 FTS 全文索引、不加任何广告位。

## 4. Android 原生实现技术指导

### 4.1 权限与 Manifest 配置
在 [AndroidManifest.xml](../../app/src/main/AndroidManifest.xml) 中补充：
- `<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW" />`
- `<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />`
- `<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE" />`（targetSdk 34+ 前台悬浮窗服务需声明 `foregroundServiceType="specialUse"` 及对应 `<property android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE" ... />`）。
- 注册 `FloatingAssistantService`（`android:exported="false"`）。

### 4.2 全局悬浮窗与 Compose 宿主关键坑点
悬浮球与悬浮面板建议采用 **Foreground Service + `WindowManager` + `ComposeView`** 实现，以保持与主 App 完全一致的 `MemorandumTheme` 视觉风格：

1. **Lifecycle / SavedState 注入（必做）**：
   - `WindowManager` 直接添加 `ComposeView` 时没有 `Activity` 宿主，必须为 `ComposeView` 手动绑定自定义的 `LifecycleOwner`、`ViewModelStoreOwner` 和 `SavedStateRegistryOwner`（通过 `setViewTreeLifecycleOwner`、`setViewTreeViewModelStoreOwner`、`setViewTreeSavedStateRegistryOwner`），否则 Compose 会在 `attach` 时直接崩溃。
2. **剪贴板读取焦点限制（Android 10+ 必读）**：
   - Android 10（API 29）起，只有**当前拥有输入焦点的窗口**或默认输入法才能读取剪贴板。
   - **解决方案**：
     - 悬浮球（收起态）使用 `FLAG_NOT_FOCUSABLE`，避免抢占底层微信/QQ 的输入与返回键。
     - 悬浮面板（展开态）必须**移除 `FLAG_NOT_FOCUSABLE`**（同时配合 `FLAG_WATCH_OUTSIDE_TOUCH` 或返回键监听收起），并在用户点击「读取剪贴板」前确保悬浮面板窗口已拿到窗口焦点（必要时延迟一帧或通过 `composeView.requestFocus()` 获取焦点后再调 `ClipboardManager`）。
     - 当面板需要输入姓名/编辑文本时，同样依赖可获取焦点的 `LayoutParams` + `SOFT_INPUT_ADJUST_RESIZE` 正常拉起系统软键盘。
3. **依赖注入**：
   - `FloatingAssistantService` 使用 `@AndroidEntryPoint`，直接注入 `PersonRepository` 与 `AppPreferences`，在 Service 生命周期内使用 `SupervisorJob() + Dispatchers.Main.immediate` 管理状态流，与独立 App 共享同一份单例 `AppDatabase` 和 `PersonRepositoryImpl`。

### 4.3 数据库与领域层扩展建议
1. **新增实体 `ConversationEntity`**（`data/local/entity/Entities.kt`）：
   - 字段：`id: Long`（主键自增）、`personId: Long`（外键关联 `persons.id`，`onDelete = ForeignKey.CASCADE`，加索引）、`content: String`、`source: String`（`"CLIPBOARD"` / `"MANUAL"`）、`conversationTime: Long?`（可空）、`createdAt: Long`。
2. **数据库版本升级**：
   - `AppDatabase` 从 `version = 4` 升至 `version = 5`（当前 Demo 阶段仍沿用 `fallbackToDestructiveMigration` 时，记得同步把 `AppPreferences.KEY_SEEDED` 升级为 `"seed_done_v5"`，确保默认关系与默认分类在重建表后能正确写入）。
3. **领域模型与 Repository**：
   - 新增 `ConversationSource` 枚举（`CLIPBOARD("剪贴板")`, `MANUAL("手动输入")`）与 `PersonConversation` 数据类。
   - `Person` 模型可增加 `conversations: List<PersonConversation>`（或在 `PersonWithEntries` 中一并 `@Relation` 查询，保持单向数据流实时刷新），`PersonRepository` 增加 `saveConversation(...)`、`deleteConversation(...)` 与 `observeRecentConversations()`。
4. **偏好存储扩展（`AppPreferences`）**：
   - 增加 `floatingAssistantEnabled: Boolean`、`floatingBallIsLeft: Boolean`、`floatingBallYRatio: Float`（用比例而非绝对像素，适配横竖屏与不同分辨率）。

## 5. 推荐开发与验证顺序

1. **数据层先行**：补齐 `ConversationEntity`、`ConversationDao`、`PersonConversation`、Mapper 与 `PersonRepository` 接口/实现，确保 `AppPreferences` 种子 key 同步递增并写好单元测试。
2. **独立 App 界面**：先在 `HomeScreen` 接入悬浮助手开关（含权限引导）、在 `DetailScreen` 接入「记忆词条 / 原始对话」双 Tab 展示与删除，保证无悬浮权限时也能完整验证数据流。
3. **悬浮窗服务**：实现 `FloatingAssistantService`（悬浮球拖动/贴边记忆 + 白色便签卡片三模式切换 + Android 10+ 获焦读取剪贴板 + 快速建人自动选中）。
4. **真机专项验证**：由于 `SYSTEM_ALERT_WINDOW` 和跨应用剪贴板读取受系统 ROM 策略影响较大，必须在真实 Android 设备（建议 Android 13/14+）上实测：微信复制 → 点悬浮球 → 读取剪贴板 → 选人/快建 → 保存 → 切回独立 App 查看详情同步。
